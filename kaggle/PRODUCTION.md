# Full-corpus screening on Kaggle · two T4 GPUs

Repository input: `data/translated/humanoid_patents_en.zip`; translation provenance: `data/translated/humanoid_patents_en_summary.json`. Published filtered subset: `data/filtered/filtered_patents.zip`. The example `/kaggle/input/` paths below are platform mounts, not repository paths.

This is the **production-path implementation**, separate from `kaggle/run.py`'s 100-family development tests. It has offline regression tests; **a live two-T4 throughput/memory test is still required** before starting the entire corpus.

## Input contract

Attach the completed translation dataset under Kaggle **Add Input**. Accepted formats:

- `humanoid_patents_en.csv`, or
- a `.zip` archive containing **exactly one** CSV, e.g. `humanoid_patents_en.csv`.

The expected schema is the output of `src/translate_abstracts.py`: original fields `docdb_family_id,year,title,title_language,abstract,abstract_language,matched_cpcs`, plus `abstract_en,translation_status`. Other metadata columns are retained. The runner requires a unique nonempty DOCDB family ID and nonempty `abstract_en` for **every row**; it rejects failed/incomplete translation statuses. It does not automatically translate non-English input, infer English content from `abstract`, or silently skip records.

Recommended: attach the translation `progress.summary.json` generated by `src/translate_abstracts.py`. The runner requires `incomplete: 0`, no `stop_reason`, and `completed` equal to the input row count. Missing source abstracts were excluded by the translator; verify expected eligible family counts before screening. Without the summary, use `--expected-rows N` from a separately validated source count (or at least inspect the preflight count).

## Single-command process

In a Kaggle Notebook select **GPU T4 x2**, enable Internet, provide `HF_TOKEN` as a Kaggle secret when required, and clone/pull the repository. Run from the repository root with Python 3.12+:

```bash
python kaggle/production_run.py \
  --input /kaggle/input/translated-patents/humanoid_patents_en.zip \
  --translation-summary /kaggle/input/translation-summary/progress.summary.json \
  --check
```

The `--check` stage verifies IDs, required English text, translation statuses, expected counts and input digest, then stages deterministic disjoint shards. It uses **no GPU, model weights or external network**. For actual screening, rerun the same command **without `--check`**:

```bash
python kaggle/production_run.py \
  --input /kaggle/input/translated-patents/humanoid_patents_en.zip \
  --translation-summary /kaggle/input/translation-summary/progress.summary.json
```

Substitute the actual Kaggle dataset paths. The runner fails unless **exactly two visible T4 GPUs** are present, verifies each GPU has at least 12 GiB, downloads/reuses the pinned Perplexity Flash v1.2 model, applies the same exact FP16 patch as the successful single-T4 pilot, prepares dependencies, and then starts **two independent Python processes**, setting `CUDA_VISIBLE_DEVICES` for each. Each process loads a separate native FP16 model; GPU memory is not pooled. Assignment is by stable SHA256 hash of DOCDB family ID, not semantic/content filtering.

By default, outputs are under `/kaggle/working/humanoid-production/`. Specify `--production-dir` to isolate a benchmark or rerun with a different source/model. `--checkpoint` overrides the model cache. `--skip-install` only applies when dependencies are already correct.

## Outputs and resume behavior

- `production_manifest.json`: source SHA256, pinned model/revision, prompt digest, two-worker configuration and provisional threshold; refuses incompatible resumes.
- `shards/worker_0.csv`, `shards/worker_1.csv`: complete disjoint normalized English-only inference inputs; `shards/family_order.csv` retains input ID sequence.
- `worker_0/predictions.jsonl`, `worker_1/predictions.jsonl`: append-only per-family journals written by the existing native model runner; separate model provenance files and completed worker CSVs.
- `predictions.csv`: **every** input DOCDB family, one probability and one provisional binary decision, in source order.
- `filtered_patents.zip` containing `filtered_patents.csv`: only provisional relevant families, retaining *all* original metadata and adding `probability_relevant,model_decision`.
- `production_summary.json`: input/output counts, keep/discard counts, per-shard counts and SHA256 digests.

On interruption, rerun the **same command** with the **same source file and production directory**. The workers reuse their existing journals and rescore unfinished IDs. A worker failure prevents a premature merge; the merge refuses missing/duplicate/unexpected IDs, invalid probabilities, contradictory decisions, or changed source data. Never manually mix worker journals from different runs. If a previous process was hard-killed and left `.screening.lock`, verify **both workers are stopped** before removing that stale lock and restarting.

## Scientific and operational constraints

- **0.5 is exploratory**, not a prevalence-calibrated production threshold. Keep **all** probabilities so an independently established threshold can be applied later without rerunning the model. Treat `filtered_patents.zip` as a provisional subset, not the only canonical research data.
- Pilot accuracy estimates are conditional on AI-provisional, purposively constructed labels; they do not prove real-world production precision or recall.
- The per-family `model.decide()` API is sequential **within** each GPU worker. Actual throughput, OOM risk and session runtime limit are not yet verified for concurrent T4 model replicas.
- Before the full run, conduct a 1,000–5,000-family benchmark from the completed translated corpus, using its **own** output directory. Check two process/GPU utilization, FP16 memory headroom, throughput, normal completion and restart after interruption. A Kaggle session may time out before an entire corpus finishes; persist the output directory between sessions (Kaggle working files are not automatically durable across all sessions).
- The output is patent-abstract relevance screening. It does not itself perform applicant normalization, longitudinal landscaping or patent valuation.

Offline tests: `python -m unittest discover -s kaggle/tests -v`.
