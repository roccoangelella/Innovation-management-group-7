# Deployment and execution

TIP/PATSTAT extraction runs in TIP; private endpoint translation runs locally under Python 3.12+ and is independent of screening.

Kaggle pilot: enable GPU and Internet, then clone the repository, change into its root, and run `python kaggle/run.py`. The 100-family original-English input is committed at `samples/random_100/humanoid_100_abstracts_en.csv` and discovered automatically. No translation or sample upload is required. Downloading the private Hugging Face checkpoint may require the `HF_TOKEN` Kaggle secret.

To evaluate the supplied AI-assisted labels, attach `humanoid_100_manual_labels.csv` as a Kaggle Dataset; the launcher finds it uniquely under `/kaggle/input/**/`, validates IDs, then runs `kaggle/evaluate.py` after scoring. Its outputs under `/kaggle/working` are `predictions.csv`, `evaluation.json`, `evaluation_cases.csv` and state/provenance files. For an existing predictions file, call `kaggle/evaluate.py` directly. See `kaggle/README.md`.

Current behavior uses a pinned native Decider checkpoint, local BF16→FP16 loader patch and one CUDA GPU. The first observed Kaggle run downloaded the checkpoint but failed at import because torch 2.14.0/CUDA 13.0 conflicted with Kaggle's torchaudio/CUDA 12.8. The launcher now removes *only* the optional torchaudio package and verifies `transformers.AutoProcessor` in a fresh interpreter. Rerun from the current clone with `git pull --ff-only` and `python kaggle/run.py` to reuse the existing checkpoint; avoid nested clones. This changes the notebook's ephemeral Python environment, so a separate audio workflow would need compatible TorchAudio installed. Successful GPU model inference remains unverified.

## Curated challenge in Kaggle

After pulling main from the repository root, run `python kaggle/run.py --challenge`. This selects the **single combined** `samples/humanoid_challenge_100/challenge_100_labeled.csv` as both abstract input and post-inference label source without external dataset attachment and writes all predictions/evaluations/journals to `/kaggle/working/challenge_100/`. For a separately uploaded combined CSV, run `python kaggle/run.py --dataset /kaggle/input/.../dataset.csv --output /kaggle/working/custom/predictions.csv`. The legacy `--input PATH --labels PATH` interface remains available. The model receives only abstract text, never label/annotation columns. The first random sample remains unchanged and the new outputs cannot collide with its manifest. GPU inference on this new challenge has not yet been observed.

## Implicit semantic challenge

From the cloned repository root after pulling main: `python kaggle/run.py --semantic-challenge` (`--check` for input-only preflight). The launcher automatically selects the single `samples/semantic_challenge_100/semantic_100_labeled.csv` and writes outputs into `/kaggle/working/semantic_100/`; it never reuses the previous challenge journal. Only source abstract enters `screen.py`'s model request; labels and rationale go to `evaluate.py` afterward. The 40/60 labels are AI-provisional and intentionally treat biped-specific technologies as relevant, broader than the earlier strict humanoid-only prompt. No live GPU evaluation of this set has been seen.

The generated `samples/humanoid_semantic_holdout_100/semantic_holdout_100_labeled.csv` is a 100-row combined source-abstract and AI-provisional-label file; it is **not** the existing `--semantic-challenge` input. Run `python kaggle/run.py --dataset samples/humanoid_semantic_holdout_100/semantic_holdout_100_labeled.csv --output /kaggle/working/semantic_holdout_100/predictions.csv` in the cloned Kaggle repo with GPU/Internet and cached HF weights. ## GitHub Actions Gemrouter translation completion — added 2026-11-10

`src/complete_translation.py` reads the committed incomplete `humanoid_patents_en.zip` and immutable `humanoid_patents.zip`, reconstructs the existing successful translations into an ignored local journal after source-ID/metadata checks, calls `src/translate_abstracts.py` only for missing nonempty abstracts, and creates a full normalized single-CSV ZIP. `abstract` and `abstract_en` are English; `abstract_language` still records the original source language, while original source titles are unaffected. The workflow `complete_translation.yml` requires repository GitHub Actions secrets `GEMR_API_KEY` and `LLM_ENDPOINT` (with `GEMROUTER_API_KEY` / `GEMROUTER_ENDPOINT` aliases), and `contents:write` permission to publish to main. The endpoint URL appears only in the ignored ephemeral translator manifest, never in the committed summary or archive. Existing partial ZIP is replaced and `humanoid_patents_en_summary.json` committed **only if every eligible source family has a nonempty English abstract** and `kaggle.production.inspect_input` passes, the compression is valid, and the source/seed Git blobs have not changed remotely. An incomplete or failed run preserves the initial archive and uploads checkpoint progress as an Actions artifact. Manual re-dispatch is supported. Before using this output for screening, confirm the completion summary reports `incomplete=0`. The live endpoint and GitHub push remain to be observed.

The workflow now uses `actions/download-artifact@v4` to load that journal from the chosen previous run ID (default `42849164410`), validates all seed/extra IDs and source-language assignments, reconstructs the private manifest and resumes only missing family IDs. Source/seed validation runs on workflow push without API traffic. **Translation and publication only run on `workflow_dispatch`**: after Gemrouter quota is restored, use Actions → Complete Gemrouter patent translations and publish English corpus → Run workflow; select the latest run ID with a valid journal (default references the first failed run). If this run also stops, use its new run ID in the following dispatch. The checkpoint is now reuploaded with 30-day retention on every validation/attempt. Ensure the artifact has not expired before resuming. Do not expose the journal or endpoint secrets in ordinary public files. Neither rate-limit reset time nor actual resumed API success is established until a subsequent run.


## Explicit one-time resume, 2026-11-11

To fulfill the user's explicit request to restart translation through this GitHub integration, the workflow supports a narrowly gated push-triggered translation and publish path only when the head commit message exactly matches `Resume Gemrouter translation from verified checkpoint 42857129812`. The default verified resume checkpoint is now run `42857129812` (which restored and validated 236,769 completed family IDs, 769 pending). Normal pushes continue to validate the checkpoint without sending API requests. This does **not** bypass HTTP 429 quota enforcement: a renewed rate/quota response stops the job, preserves the canonical ZIP, and uploads a new progress artifact. Following a successful completion, the workflow publishes only after 100% eligible family coverage and hash/ZIP validation. Later re-execution should use `workflow_dispatch` with the latest journal artifact ID.


## Two-T4 production submission and Weights & Biases (2026-11-11)

GitHub Actions `.github/workflows/kaggle_production.yml` securely uses `KAGGLE_API_TOKEN` and `HF_TOKEN` to submit an account-private Kaggle GPU-T4-x2 notebook and provision the pinned restricted HF model into an account-private Kaggle dataset. The GitHub-only `WANDB_API_KEY` posts aggregate live progress from Kaggle logs to project `humanoid-patent-filtering`. No credentials or patent contents enter W&B telemetry. The notebook pins a Git commit and checks the final translation summary's 237,538 eligible rows. Workers retain append-only journal state and emit progress, speed, ETA and optional actual GPU utilization/memory. A 300-minute first session exports a resumable checkpoint to Kaggle output; later sessions can attach it as private data, preserving provenance. Operational success and initial model mirror access remain subject to real workflow logs; do not claim full-corpus labels from mere kernel submission.
